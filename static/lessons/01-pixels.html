第 01 课 · 图片与数字

电脑怎样“看”一个手写数字

不需要会画画或编程：先把一张小图片当成方格纸，再用四则运算把格子的明暗变成数字。

1. 一个格子就是一个像素

目标：知道像素是图片上的一个小格子，灰度值是描述它有多亮的数字。

具体例子：灰度值 0 是黑，255 是白，128 大约是中间亮度；一张 28 × 28 的图有 28 × 28 = 784 个格子。MNIST 是带着“正确数字”答案的手写图片集合，通常是黑底、较亮的笔画。

先猜：一个灰度值为 0 的格子和一个值为 255 的格子，哪个更亮？

动手：先在纸上画一个 2 行 2 列的方格，填入 0、255 / 128、0；把 0 的格子涂黑，255 的格子留白，128 的格子涂成中间亮度。下一步再看电脑如何把这些数缩到 0～1。

核对：255 更亮；纸上的四个格子已经是一张很小的数字图片。

复述：图片不是电脑理解的“一个数字”，而是许多像素值排成的表格。

下一步：把 0 到 255 的数字换成更容易计算的范围。

2. 把明暗缩到 0 到 1

目标：用除法理解归一化——按同一比例缩放数值，保留明暗顺序。

具体例子：把每个灰度值除以 255：0 ÷ 255 = 0，255 ÷ 255 = 1，128 ÷ 255 ≈ 0.502。≈ 表示四舍五入后的约数；这不是把较亮的格子变暗，而是换一把尺子。

先猜：原来的 51 缩放后是 0.2、0.5，还是 1？

动手：在纸上或 Windows“计算器”里算 51 ÷ 255。再点击下方小方格，把值从 0（黑）切换到 0.5（灰）和 1（白），观察旁边数字表怎样同步变化；互动区显示的是已经缩放后的值，不是让你输入 51。

自测：灰度值 51 除以 255 后是多少？

核对：51 ÷ 255 = 0.2；缩放后的值仍在 0 到 1 之间。

复述：归一化是每个格子除以同一个数，这里是 255，并不改变格子的排列。

下一步：看电脑怎样记录一张图或一组图的尺寸。

3. 一张图片与多张图片

目标：记住一张图是 28 × 28 格；多张图只是把这样的图片放在一起。

具体例子：一张图有 28 × 28 = 784 个像素；两张同样大小的图共有 2 × 784 = 1568 个像素，但每张仍是 28 × 28，不会变成一张更宽的图。

先猜：放入 2 张图后，每张图会从 28 × 28 自动变成 56 × 28 吗？

动手：在纸上画两个独立的 2 × 2 小方格，数数是“两张、每张四格”，还是“一张八格”；若已安装依赖，可在项目文件夹运行 python examples/01_pixels_and_tensors.py，无需下载 MNIST。

核对：仍是两张各 28 × 28 的图；总共 1568 个像素，并不是把两张拼成一张。

复述：增加图片张数，不会改变单张图片的高、宽或像素含义。

选修：程序如何用四个数字记住一组图

张量是按固定尺寸排列的一组数字。程序把两张灰度图记作 (2, 1, 28, 28)：依次是图片张数、每张图的通道数、高、宽。通道是记录一种颜色信息的一层表格；灰度图只有 1 层。暂时记不住这四个数也可以继续下一课。
