# 从像素到训练：四步读懂这个 CNN

这份路线图适合第一次接触神经网络的读者。按顺序运行四个**独立脚本**：前三个自己生成数字，不需要下载 MNIST；第四个才读取 `data/mnist.npz`。建议每跑一步，先猜输出形状，再看代码和结果。

## 准备

在项目根目录运行命令。需要 Python、NumPy、PyTorch；如果依赖装在项目的 `libs/`，示例会先导入 `paths.py` 找到它们。第四步要先运行 `python download_data.py`，得到 `data/mnist.npz`。首次下载需要联网；前三步离线即可运行。

## 1. 像素如何成为张量

```bash
python examples/01_pixels_and_tensors.py
```

读 `normalize_pixels`：一张图原本是 `(28, 28)` 的整数数组，灰度 0~255；除以 255 后成为 0~1 的 `float32`。读 `to_model_input`：在最前面加两个维度，得到 `(1, 1, 28, 28)`，依次代表**批量、通道、高、宽**。这里第一维 1 表示一次送入一张图，第二维 1 表示灰度图只有一个通道。`model.py` 的 `Conv2d(1, 32, ...)` 中的 1 正对应这个通道数。

试着回答：如果一次送入 64 张图，输入形状会变成什么？归一化后原数组有没有被改写？

## 2. 权重为什么会变化

```bash
python examples/02_neuron_and_gradient.py
```

`neuron_output` 先将输入乘以各自的权重再相加，最后经过 ReLU（负值变 0）。为了把求导单独讲清楚，下面的单权重演示**不使用 ReLU**：预测值 `w × x`，平方误差 `(w × x − 目标)^2`，对权重的导数为 `2 × (w × x − 目标) × x`。脚本会对比手算与 PyTorch 的 `backward()`，再做一次 `w ← w − 学习率 × 梯度`。只更新一次，误差就能下降；真实分类用多个权重和交叉熵，而不是这个玩具平方误差。

试着回答：学习率太大，为什么有可能越更新越差？

## 3. 卷积如何提取局部特征

```bash
python examples/03_convolution_and_pooling.py
```

`convolve2d` 让一个 2×2 小窗口在 4×4 图片上移动，每个位置做逐项乘法并求和：无填充、步长 1，输出是 3×3。这里遵照 PyTorch 的 `Conv2d`，**卷积核不翻转**，数学上叫互相关。`max_pool2x2` 再从每个不重叠的 2×2 小块里取最大值；3×3 输入会丢掉末尾一行/列，输出 1×1。脚本也用 PyTorch 核对手算卷积结果。

真实 `HandwritingCNN` 不是直接照搬这两个玩具设置：它的 3×3 卷积带 `padding=1`，使 28×28 仍为 28×28；2×2 池化再使其变为 14×14。第二组卷积、池化把它变成 7×7；32、64 分别是两组卷积产生的特征图数量。看 `model.py` 的 `features` 与 `classifier`，试着解释为什么全连接层要接收 `64 × 7 × 7` 个值。

## 4. 把各步骤连成一次训练

```bash
python download_data.py
python examples/04_minimal_training.py --epochs 1 --max-samples 512 --device cpu
```

第四步直接使用项目的 `data.load_npz`、`data.split_train_validation` 和 `model.HandwritingCNN`，**同步执行**，不会开启 Web 服务。先从 MNIST 原训练集按类别划出验证集（默认约 10%，随机种子固定），再把这两部分各自限制为最多 512 张以便练习；原测试集只打印数量，不参与这次训练或验证。这个小样本的准确率波动大，不能代表完整 MNIST 的效果。

每轮训练先 `model.train()`，再对每批执行 `zero_grad → model(x) → CrossEntropyLoss → backward → optimizer.step`；一轮结束切换为 `model.eval()`，在 `torch.no_grad()` 中计算验证误差和准确率，**不更新权重**。交叉熵直接接收模型输出的十个原始分数（logits），不要先自己做 Softmax。`epoch` 是看完选定训练样本一遍，`batch` 是一次送入的小组，`step` 是更新一次权重。

试着回答：为什么验证集不能参与 `optimizer.step()`？为什么训练准确率和验证准确率可能不同？接着去读 `train.py` 的 `_run_epoch`：它将同样的步骤放在后台线程，并把结果写入网页使用的状态，而这个例子保持同步，方便逐行阅读。

> `--max-samples` 同时限制训练和验证样本；`--epochs` 可以多跑几轮；`--device cuda` 只在 CUDA 可用时使用。若数据不在默认位置，可用 `--data 路径` 指定自己的 `mnist.npz`。示例不保存权重，也不报告最终测试集成绩。

完成四步后，可用 [实验记录模板](experiments.md) 有控制地调整训练轮数与样本量，先提出假设，再比较结果。

## 正确理解训练结果

- 模型输出的 **logits 是原始类别得分**，并非概率。训练中的 `CrossEntropyLoss` 内部处理这些得分；只有面向人的结果展示才使用 Softmax。
- **loss 与准确率不等价**：同样预测对一张图，模型的置信程度改变也会使 loss 改变。训练中累计的准确率来自不断更新的模型和训练模式；验证准确率来自轮末固定模型的评估模式，两者不是同一时刻的严格对照。
- **验证集**不更新权重，但可用于观察和选参数；**测试集**在确定方案后才使用，是最终考试。反复按测试成绩选择参数也会造成信息泄漏。
- 可视化的首层特征图显示某些位置的响应强弱，但不能保证“第 1 个核一定识别竖线”。一个通道的语义通常不是确定的自然语言概念。
- Dropout 是训练模式中的随机失活，评估模式会关闭。关闭 Dropout 不意味着一定过拟合；只有根据训练/验证变化才能判断。
- 固定随机种子有利于复现，不能保证不同设备和库版本的数值逐位相同。CPU 耗时和识别表现取决于本地环境。
- 手写识别先把笔画裁剪、缩放并居中。模型主要学了 MNIST，照片、彩色复杂背景或多个数字可能被误判；Softmax 的最高概率不是“保证正确”的承诺。

## 推荐源码阅读顺序

`examples/01` → `examples/02` → `examples/03` → `model.py` → `examples/04` → `data.py` → `train.py`（先 `_run_epoch`，再 `_evaluate`，最后状态/锁）→ `server.py` → `static/`。如果暂时读不懂线程，先只运行同步的例子 04；Web 训练器在其外围增加状态、并发和可视化，不改变核心的五步训练顺序。
