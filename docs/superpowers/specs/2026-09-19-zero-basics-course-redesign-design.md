# 从零开始理解手写数字识别：课程与代码整理设计

日期：2026-09-19
状态：用户已审阅并批准；这是设计依据，实际实现与验收结果以代码和测试报告为准。

## 1. 目标、读者与边界

读者可以没有计算机使用经验，没有接触过机器学习，也没有学过微积分。完成主线后，读者应能在 **Windows** 上按图文步骤启动课程、完成互动实验、观察训练和手写识别，并用自己的话解释模型怎样利用局部线索、怎样从有标签的例子中改进、为什么要用未参与训练的样本检查结果。**不要求**读者会写 Python、推导导数或独立重写 CNN。

课程主线放在网页，采用“先猜—动手—观察—解释”的短步骤；README 只负责引导进入课程。公式、Python 脚本、四维张量与源码阅读保留为可选进阶，不作为下一课的门槛。例子只使用读者已见过的四则运算；新术语在首次出现处解释，避免把输出分数写成必然正确的“把握”。

保留 Flask、现有模型、项目内 `libs/` 依赖方式、`start.bat` 入口和已有 `/api/*` 行为。前端使用浏览器原生 ES 模块，不引入 Vue、Node 构建步骤或运行时 CDN。学员首次安装 Python 和项目依赖、准备 MNIST 数据可能需要网络；准备完成后的本地课程不依赖外部前端资源。整理代码不是重写训练算法或更改模型效果。

## 2. 课程主线与每课交付

| 课 | 学员能完成的最小任务 | 核心直觉 | 进阶内容不阻挡主线 |
| --- | --- | --- | --- |
| 00 开始使用 | 找到项目文件夹，按 Windows 指引检查 Python、安装依赖并打开网页；核对预期画面 | 文件、文件夹、程序、浏览器和本地网页的区别 | 终端命令及路径原理 |
| 01 数字图片 | 点亮方格，把一个小图案读成数字表，再观察 28×28 图片 | 模型接收数值，而非直接“看见数字 7” | 张量、数据类型和维度 |
| 02 找局部线索 | 先手算模板与图片的第一格，再移动模板观察结果 | 对应位置相乘、求和、滑动形成局部线索；池化是摘要而非万能识别 | 步长、填充和尺寸公式 |
| 03 组合成网络 | 根据图示连接局部线索、汇集线索和分类结果 | 各层分工；特征不能总被命名为某个具体形状 | 完整 CNN 结构、通道数与参数 |
| 04 让机器学习 | 先猜一次调整的方向，再观察多轮训练变化 | 标签、预测、误差、更新与轮次；先用数值试探建立直觉 | 导数与反向传播推导 |
| 05 检查是否真会 | 对照训练与未参与训练的图片，找出错例并解释指标 | 验证、准确率与过拟合；高输出分数不保证判断正确 | 更严格的实验设计与混淆矩阵 |
| 06 自己试一试 | 手写数字、查看结果，做一次只改一个可控条件的比较 | 预测的局限，以及怎样谨慎比较训练实验 | Python 修改与独立扩展 |

每课由若干短步骤组成，每步固定有一句目标、一个具体例子、“先猜”、一个操作、即时反馈、一句复述提示，以及上一步／下一步。回答错误时解释差异，不仅显示红色叉号；术语可在当前步骤直接查阅。允许跳课和返回，不以测验结果硬锁章节。课程进度只是本机便利记录，不等同于真实能力证明。

00 课的安装说明从 Windows 文件资源管理器、文件夹位置、打开安装程序和启动脚本讲起，提供每步预期结果、常见失败及可执行的下一步。不要把“已安装 Python、会用终端、知道 PATH”作为隐含前提。需要下载数据时明确说明用途、网络要求和如何重试。已有 `examples/` 是选修练习，不应出现在第一屏的必做步骤里。

## 3. 页面结构与交互边界

- **开始页**：课程地图、Windows 启动帮助、环境和数据状态。没有 MNIST 时，00—03 课等无需训练数据的内容仍可阅读和操作；进入依赖数据的功能时才展示准备步骤。
- **逐步学习页**：统一步骤导航、操作区、反馈区与就地术语说明。小屏上改为纵向布局，键盘可以到达每个控件，焦点状态清晰。
- **独立活动**：像素方格、卷积第一格／滑动、网络线索、调权重与实验比较各自管理事件监听和动画；离开步骤时执行清理。
- **训练观察页**：训练控制、状态、曲线、评估与错误提示分别渲染。初学者先看到“观察什么”，再看到完整参数设置。
- **手写识别页**：画板、输入预览、预测与中间线索各有清楚的职责；没有已训练模型时显示原因和返回训练步骤的入口。
- **进阶入口**：从相关步骤链接到独立说明；离开进阶页可返回原学习位置。

课程目录是唯一的导航数据源：每项声明编号、标题、内容路径和可选互动模块。切换时装载该课 HTML，并通过 `import()` 只加载所需的互动或功能模块；模块暴露明确的挂载／清理接口，不通过全局变量相互调用。HTML 不写内联 `onclick`。简单的文字解释保持为可编辑的语义化 HTML，不把整课嵌入大型 JS 字符串。

浏览器本机存储只记当前课程位置等便利信息；读写失败、清除存储或首次访问时，课程照常从开始页运行。用户输入与 API 文本用安全的文本节点呈现；课程 HTML 是仓库自带的静态内容，不加载远程可执行脚本。所有 ES 模块通过 Flask 服务加载，**不要求也不支持直接双击 `index.html` 的 `file://` 用法**。

## 5. 后端兼容与数据流

**启动与健康状态**：`start.bat` 不再因尚未下载 MNIST 而阻止打开课程；依赖缺失仍明确提示安装步骤。`server.py` 保持现有懒构造 Trainer 的行为。课程静态内容不因 `/api/health` 返回“缺少数据”而消失；训练和识别入口用该状态提示准备数据。准备数据后仍按原有下载、训练流程工作。

**训练与预测**：前端各功能只通过共用 API 客户端调用现有端点，不直接依赖其他页面控制器。训练页保持单一轮询循环，离开时停止；请求重叠时不再发第二个状态请求，短暂网络失败显示可重试状态而非无限空白。操作失败保留服务器错误信息的可理解部分，提示学员下一步能做什么。识别输入仍使用现有 28×28 契约，不改变 HTTP 返回结构。

**渐进后端拆分**：先固定行为测试，再抽出设备选择和存档校验／读写辅助逻辑；仅在锁语义和异常语义受测试保护时抽出预测纯计算。`Trainer` 的方法、线程与锁生命周期、`_load_data` 覆盖点及状态所有权暂时不搬迁。`train.py` 继续导出 `Trainer`、`DATA_FILE`、`hardware_info`、`resolve_device`，服务器仍可替换 `server.Trainer`；保持原有存档格式、设备选择和命令行入口。这样优先降低大文件的职责复杂度，而不是为短文件制造跨模块共享状态。

**非目标**：不更改网络结构、训练数学、超参数默认值、数据集划分、已有 API 字段和存档格式；不把已有测试的替身接口改成另一套。发现某项拆分必须改变这些契约时先缩小拆分范围，而不是顺手扩大改造。

## 6. 测试与验收

改造前基线：`python -m unittest discover -s tests -v` 的 **22 项测试通过**。这只说明现有自动化测试通过，不说明教学内容已合格。

1. **Python 契约与回归测试（必跑）**：保留现有训练、设备、存档及 API 测试；补上无数据仍可打开课程、训练入口返回可理解错误、启动路径兼容、`Trainer` 的继承／`_load_data` 覆盖点及存档往返等场景。每抽出一个后端职责就跑相关用例和完整测试。
2. **真实浏览器测试（开发依赖）**：使用 Python Playwright 与独立的浏览器测试命令；它不进入学员依赖，也不引入前端构建。覆盖开始页到课程步骤、前进返回及刷新、本机存储不可用、核心互动的正确／错误反馈、缺数据和 API 失败提示、训练及识别页面连接、离页后停止轮询、键盘焦点和约 400px 宽布局。界面错误状态可用模拟 API 响应；真实训练行为仍由 Python 集成测试验证。未安装 Playwright 或浏览器时报告“未运行”，不能冒充通过。
3. **人工零基础验收**：逐课检查新词是否当场解释、例子能否只靠已教授的四则运算完成、读者在动手前是否知道观察什么、做错是否知道原因。在 Windows 新手路径从找文件夹开始实际走通安装和启动；不读源码、不学导数也能完成主线，并能复述卷积线索、训练与验证区别以及预测分数的局限。人工验收记录遇到的卡点，不用测试数量代替学习效果。

课程核心的数值演算和输入校验须有确定的边界用例；内容链接与目标元素由静态契约测试检查，真实点击行为由浏览器测试检查。检查离线使用时不发起外部前端资源请求。验收结果明确区分“通过”“失败”“未运行”。

## 7. 实施顺序与完成定义

先补需要的行为保护，再调整 `start.bat` 和开始页，使无数据的读者能进入课程；逐课迁移内容及独立互动；随后替换训练／识别旧前端全局调用，移除不再使用的大页面结构和重复样式；最后在回归测试保护下逐步抽出后端辅助职责、整理文档与旧文件引用。每阶段保持可启动，不长期并存两套互相矛盾的课程入口。

完成时应能从 README 找到 Windows 操作说明、在无 MNIST 时进入课程、沿主线不用编程或微积分完成互动、在有数据时继续训练与识别；页面 JS 没有内联事件和跨文件隐式全局依赖，主要职责分布在可单独理解的小模块。已有 Python 测试、约定的浏览器测试和人工新手验收分别报告真实结果。本文经审阅后再编写详细实施计划；设计文档本身不表示已获准开始改造。
