# 实验记录：每次只动网页里的一个旋钮

学到 [学习指南](learning-guide.md) 的 **06 自己试一试** 时，可以用本页记录两次训练：到 **04 让机器学习** 想观察真实训练时，先按 [Windows 指引第 5 步](windows-start.md#5-到训练课再下载手写数字数据) 下载 MNIST；打开网页及学习前面的章节不需要提前下载。不需要修改代码或运行 `examples/`。先猜结果、再改一个设置、最后看验证数据，不用测试集成绩挑参数。一次运行不能证明一般规律。

## 先做基线

1. 从 **06 自己试一试** 进入训练页的参数实验区，选 **CPU**，确认训练轮数 **6**、学习率 **0.001**、批大小 **64**、Dropout **0.3**。若页面里已有别的数，改回这些数。
2. 点参数区的「应用参数并重新训练」，等到状态显示「已完成」。此操作会**从头训练**，不是接着上一次训练；CPU 所需时间因机器而异。
3. 在训练页看每轮验证准确率、损失曲线；在参数实验区看本机实验记录里的最终**验证准确率与验证 loss**。把实际数字填到下表，别猜一个“应该达到”的目标。

| 运行 | 学习率 | 其他设置（轮数 / 批大小 / Dropout / 设备） | 运行前预测 | 最终验证准确率 / 验证 loss | 看到的曲线与疑问 |
|---|---:|---|---|---|---|
| 基线 | 0.001 | 6 / 64 / 0.3 / CPU |  |  |  |
| 对照 | 0.0001 | 6 / 64 / 0.3 / CPU |  |  |  |

## 只改学习率，做一次对照

回到参数实验区，**只**把「学习率 lr」改为 **0.0001**，其他四项保持与基线一致；点「应用参数并重新训练」。完成后记下同样的指标。学习率相当于每次调整参数的步幅：较小的值在相同轮数内可能学得更慢，但不保证每条曲线都严格下降，也不保证准确率一定更低。

若中途暂停、取消或训练失败，这次不要填进“完整运行”的对照格；网页的本机实验记录也只列完整结束的运行。基线和对照都记下设备，避免把 CPU 与 GPU 的耗时直接当成学习率差异。

## 怎么解释结果

- 比较的是**相同轮数下的观察**，不是“0.0001 永远更好/更差”。固定参数和项目随机种子有助于比较，但机器、库版本及数值计算仍可能带来差异；一次差距不足以确立因果规律。
- 观察验证指标与训练曲线的整体趋势，不要只看某一批图片的 loss；训练中的准确率来自不断更新的模型，而验证准确率是轮末固定模型的评估，两者不是同一时刻的严格对照。
- 网页在每次完整训练结束也显示独立测试成绩。**不要拿这几次测试成绩来选学习率**；反复用测试集调参，就不再是独立的最终考试。
- 想试轮数、批大小或 Dropout，先回到同一基线，再一次只改其中一个；记录新设定、预测与实际观察。改轮数同时改变了训练次数与运行时间，不能据此断言别的因素未变。若同时改动多个设置，无法可靠区分是哪一个产生了差异。

完成后可以返回 [学习指南](learning-guide.md)；想读源码再选 [Python 与源码](advanced/python-and-source.md)。选修脚本 `examples/04_minimal_training.py` 的 `--max-samples` 会**同时**限制训练和验证样本数，因此改变该参数并不是严格只改变训练数据量的对照实验，基础实验无需运行它。
